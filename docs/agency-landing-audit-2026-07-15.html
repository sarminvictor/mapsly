Verdict on the premise: the redirect does not exist, and it never did

This is not "already fixed." There is nothing to remove. Both / and /for-agencies already are full, directly-rendered landings sharing AgLanding.tsx. The requested change is already the state of the world.

  • git log --all -S"redirect(" -- app/[locale]/(marketing-v2)/ app/[locale]/(marketing)/ → zero commits, across all branches back to root commit 4b23b2f.
  • Both /for-agencies implementations ever written render components directly. The deleted predecessor (added 94eb95c, removed acb4147) has zero redirect hits.
  • No redirect at any layer: no redirects() in next.config.ts, none in vercel.json, none in middleware.ts, zero 'use client' / router.push / window.location / meta-refresh in the agency component tree.
  • Production today: curl -L https://www.mapsly.ai/for-agencies → 200, 0 redirect hops, 449 kB of server-rendered HTML.

Where the belief most likely came from

for-agencies/page.tsx:27 declares alternates.canonical pointing at /. That is an SEO dedupe instruction to Google — it tells the crawler to consolidate ranking signals onto the homepage. It never moves a browser. It is easy to misremember as "we redirected the agency page to the main page."

Keep it. Do not convert it to a 301: /for-agencies is a live redirect target from post-signin/page.tsx:132 and owns registered localized slugs (/para-agencias, /pour-agences). A 301 would break inbound backlinks and that signin flow. The canonical is the right tool — its target host is what's broken (fix 1).

The white page

Status: unproven as a reproduced failure — one strong candidate

No browser was run (per the manual-testing rule). The chain below is established from production HTML byte layout and measured cache/timing headers, not a live repro.

Candidate: a render-blocking Google Fonts stylesheet for fonts the page never uses

app/layout.tsx:50-51 emits a fully render-blocking cross-origin stylesheet for Fraunces + Inter + JetBrains Mono + Montserrat. It is the only rel="stylesheet" in the document.

  • The agency landing applies zero rules from those families — counting font-family rules in the served 76,127-byte inline <style>: Fraunces = 0, Montserrat = 0, JetBrains Mono = 0. The tree is entirely .fb-scope using self-hosted Space Grotesk / Bricolage via next/font.
  • A pending stylesheet blocks first paint and defers execution of subsequent scripts. The page's content ships inside <div hidden id="S:1">, revealed by an inline $RC("B:1","S:1") call — so a stalled googleapis delays both paint and reveal.
  • cache-control: private, max-age=86400 on that CSS explains "first load only." Third-party variance — China blocks fonts.googleapis.com outright, plus corporate proxies, Pi-hole/NextDNS, privacy extensions — explains "some users."

Why not called proven: stylesheets time out and error rather than blocking forever, so this yields a long white interval, not a permanent white page. Honest reading: a real, unnecessary render-blocking third-party dependency on the two highest-traffic routes, plausibly long enough to be reported as a white page.

Confirmed latent bomb — do not flip the CSP to enforcing

middleware.ts:12-15 currently instructs a future maintainer: "FLIP TO ENFORCING after a browser pass confirms no legitimate resource is reported." Following that instruction would white-page 100% of users on every route.

  • Policy is script-src 'self' 'nonce-<uuid>' https://js.stripe.com with no 'unsafe-inline'.
  • In production HTML, 82 script tags exist but only 63 carry a nonce. The un-nonced ones include React's streaming runtime — including the $RC("B:1","S:1") call that reveals the page.
  • www.googletagmanager.com is absent from script-src, so GA4 / Pixel / Smartlook would die silently.
  • There is no report-uri/report-to directive — so the "browser pass" gate the comment depends on has zero telemetry behind it. Report-Only is reporting to nothing.

Ruled out with evidence — do not re-litigate

  • Routing / redirect — prod is 200 / 0-hop, fully server-rendered.
  • Accept-Language locale bounce — localeDetection: false (i18n/routing.ts:10). es-ES, fr-CA and a NEXT_LOCALE=es cookie all return 200 / 0 hops.
  • Missing for_agencies namespace in es/fr/en-CA — i18n/request.ts:15-26 deep-merges en as base, so keys always resolve. All four locales serve ~448–458 kB with a real <h1>.
  • Stale nonce vs cached HTML — 60/60 paired requests matched header nonce to body nonce. The HTML carries no etag/last-modified and never 304s, so no cache can pair a stale body with a fresh header.
  • Hydration crash — AgLanding is 100% server components (zero 'use client' in the agency tree).
  • Missing error.tsx — Next 16 always wires a builtin global error boundary; the build at HEAD emits /_global-error (9,361 B) with a working Reload button.

To instrument (~10 min in DevTools — Viktor's call per the manual-testing rule)

  1. Load /for-agencies with fonts.googleapis.com blocked (DevTools → Network → request blocking) + hard reload. If it stays white past the CSS timeout, the candidate is confirmed.
  2. Same URL with JS disabled — confirms how much of the page is $RC-gated.
  3. Slow 3G, cold cache — record time-to-first-paint delta with and without the fonts link.
  4. Before any CSP work: add a report-to endpoint and keep Report-Only, so the flip has evidence behind it.

Fixes, ranked by impact ÷ effort

1. Point CANONICAL_ORIGIN at the host that actually serves 200. effort: low

Set lib/seo/canonical.ts:19 to process.env.NEXT_PUBLIC_SITE_URL ?? "https://www.mapsly.ai", delete the 11 local redeclarations in favour of importing it, point app/layout.tsx:10 metadataBase at the same constant, and add a guardrails.json grep banning the literal "https://mapsly.ai" outside that file.

Why: every canonical, every hreflang, all 32 sitemap URLs, robots.txt's Sitemap line and the Organization JSON-LD name a host that 307s. The repo already knows www is the real host — lib/url/mapsly-public-url.ts:26 force-rewrites apex→www for exactly this reason. Requires one decision: www vs apex as primary (see below).

2. Move the Google Fonts link out of the root layout. effort: low — ~20 lines between two layouts, no component changes

Move the fonts <link> (app/layout.tsx:50-51), its two preconnects (:21-27) and the two FreightBigPro preloads (:31-45) into the legacy (marketing) layout that actually consumes globals.css tokens. Add a next.config.ts headers() rule giving /fonts/:path* public, max-age=31536000, immutable.

Why: removes the only render-blocking resource — and the leading white-page candidate — from / and /for-agencies, plus 50,292 B of high-priority preload and 2 revalidation RTTs, for fonts with zero applied CSS rules on those pages.

3. Do NOT flip the CSP to enforcing. Rewrite the instruction comment. effort: low for the guard + report endpoint

Add a report-uri/report-to endpoint so Report-Only produces evidence, add www.googletagmanager.com to script-src, verify every inline script carries the nonce, and update middleware.ts:12 to record these preconditions.

4. Stop advertising locales that don't exist. effort: low

Remove the alternates.languages block from page.tsx:31 and for-agencies/page.tsx:28, and remove the three locale variants of "/" from app/sitemap.ts, while es/fr/en-CA carry no translated for_agencies copy. Gate re-enablement on a single TRANSLATIONS_LIVE flag so hreflang and content cannot drift apart again.

Why: hreflang declares four language variants of byte-identical English pages served under <html lang="en">. Google discards mis-annotated clusters, so the tags are dead weight, and the sitemap submits three URLs that canonical away.

5. Fix the /en-ca → /en-CA 307. effort: low

Drop the .toLowerCase() at i18n/pathnames.ts:81, mirror at lib/seo/hreflang.ts:56, flip the two test expectations at translated-pathnames.test.ts:126,133. A green test currently asserts the broken lowercase path. Worth the test flip regardless of fix 4.

Either render the note (Suspense-wrapped searchParams per cache-components.md Pattern 3) or delete the dead param at post-signin/page.tsx:132.

7. Delete the dead two-landing scaffolding. effort: low

Delete components/marketing/{Hero,AudienceSplit,FinalCTA}.tsx (zero importers each — they still hardcode the superseded IA and actively misled this audit). The one decision needed: www or apex?

Fix 1 needs a direction. Today the code says apex (https://mapsly.ai, 12 places) and the network says www (apex 307s → www serves 200).

Option Change Trade-off
www primary (recommended) One constant + 11 import swaps. Matches what production already serves and what lib/url/mapsly-public-url.ts:26 already force-rewrites to. No DNS/Vercel change, no risk to live links.
Apex primary Flip Vercel's primary domain, redirect www→apex. Keeps all 12 literals correct as-is, shorter URLs — but changes live redirect direction for every existing inbound link and contradicts the runtime rewrite layer.

Honesty log — 9 claims refuted under adversarial verification

Reported because several were initially the most alarming findings, and two carried recommendations that would have made things worse.

  • "<Suspense fallback={null}> is the white-page root cause" — refuted. The hidden-div/$RC structure is produced by any suspended React 19 boundary: boundary B:0 has a non-null fallback and ships the identical shape. "448 kB of invisible content" was fabricated — the hidden segment is 40,614 B; 69% is RSC flight that is never visible content under any architecture. The shape is prescribed by the repo's own cache-components.md:62 Pattern 2. Residual truth: a null fallback means the PPR static shell contains no content, so first paint waits on the dynamic render — a real LCP nit, not a white-page cause.
  • "No error boundary exists; every failure degrades to blank" — refuted. Next 16 always wires a builtin global error boundary. The recommended Sentry.captureException fix would not compile — Sentry isn't installed.
  • "First Load JS is 205.3 kB — over budget" — refuted, and inverted: the route is ~15% under at 170.4 kB gzip.
  • "The per-request nonce defeats CDN caching" — refuted by measurement: x-vercel-cache: HIT, 60/60 nonce pairs matched.
  • "globals.css is serialized three times" — surface observation true, mechanism/numbers/impact all wrong; the blamed file has no defect.
  • "mapsly.ai is not registered in Google Search Console" — factually verified (GSC lists only sc-domain:boxly.ca) but refuted as a code finding. Real process gap, wrong artifact.
