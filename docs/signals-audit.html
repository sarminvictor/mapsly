D · The flexibility model — expertise + simple settings

Your core point: show our expertise, but let users sculpt it with simple settings, not raw operator dropdowns. The answer is a small set of setting types. Every signal uses one — no free-text, no < = ≥ pickers in the common path.

The 5 setting types

  • 1 · Position scale (market-relative) — replaces a dozen "few / many" signals with one. Multi-select chips vs the cell:
    Powers Market position (rating+reviews), Search visibility (rank/traffic), Ad volume, etc. — all on real CellMetric percentiles.
  • 2 · Direction / mode switch — for things that move. One signal, pick the state:
    This fixes "Active & growing" — "growing now" = velocity↑ last 30d (real); "momentum" / "seasonal" derive from the review history (your seasonality point).
  • 3 · Platform multi-select — replaces the = Wix text box. "Built on one of […]" with a real list (Wix, Squarespace, WordPress, Shopify, GoDaddy, Webflow…) + a Not detected option. Same pattern for booking tools, chat, payments.
  • 4 · Presence toggle — Has / Doesn't have (website, booking, schema, analytics, pixel…). Fixes "Has a website" only having the yes side.
  • 5 · Strictness (today's "sensitivity") — Looser / Balanced / Stricter, shown with the actual numbers it moves. Used only where a real numeric threshold exists.
Plus, for composites: a match mode (Require all / any) and per-condition toggles inside "How it works" — so any bundle can be broken into its parts without touching raw fields.

E · UX — raw-data filters & the library

Raw-data filters are too technical

Today: field · operator dropdown (< = ≥ between) · a value box · a unit. That's a query builder, not a tool a marketer enjoys.

  • Make it a sentence, not a form. "Mobile speed is below 50" with the two underlined parts as inline taps — no separate operator column.
  • Hide raw fields by default. 90% of users live in signals. Raw stays a thin "Advanced" drawer.
  • Prefer a setting over a raw field whenever one exists (position scale instead of "reviews ≥ 50").

The signal & field library is a wall of text

  • Compact rows (name + one-line + add), not full cards.
  • Lead with ~8 starred signals; everything else behind collapsed groups.
  • Search-first with example queries ("pixel", "slow", "reviews"). Group chips to filter.
  • Separate the two tiers visually — SIGNALS (big, explained) vs raw DATA (small, secondary).

F · The plan (in order)

Position scale, mode switch, platform multi-select, presence toggle, match-mode + per-condition toggles. Rework "Active & growing", "Reputation slipping", "Flying blind"; merge the ad-pixel duplicates. All on data we already have.

2 · Mine the data we already have into new signals

Backed today (Section A/C): No website at all, Not SEO-friendly (seo_score), Losing rankings (rank-trend), Branded-only traffic, Runs video/image ads, Ads point at homepage, Unclaimed / sparse profile, Recurring complaint theme, Service gap vs market, Reputation fire (negative spike).

3 · Unblock the empty layers (then their signals turn real)

Run BusinessTech (pixel / analytics / booking / chat / e-commerce / CMS), BusinessEnrichment (AI research), and PlaybookFinding (HIPAA/ADA) on the cohort. Until then those signals stay flagged "not backed."

4 · Park what we can't back

No data source today: backlinks, ad spend band / variations / brand-hijack, price tier, hiring, affluent ZIP / density, multi-location. Don't ship signals that quietly match nothing.
