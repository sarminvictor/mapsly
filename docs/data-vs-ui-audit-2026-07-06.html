Key facts

activeCols is seeded from the goal ONCE at mount and never updated when a run finishes
modules/agency-portal/discover/components/LeadsWorkbench.tsx:346

`const [activeCols, setActiveCols] = useState(() => defaultActiveColumnsForGoal(goalResearches))` — Tom needs bought data to appear where he is looking, but the only column-seeding moment is component mount; a mid-session Enrich More purchase changes nothing on screen.

The saved localStorage view overrides even the goal seed on every revisit
modules/agency-portal/discover/components/LeadsWorkbench.tsx:546

`if (saved.activeCols !== undefined) setActiveCols(saved.activeCols)` — once ANY blob is saved (which happens on first render via the save effect at :592-618, no userTouched gate for columns), defaultActiveColumnsForGoal never runs again. So data purchased on visit 2+ stays invisible forever unless Tom opens the Fields menu himself.

defaultActiveColumnsForGoal already proves the additive pattern, but only covers goal researches at first visit
modules/agency-portal/discover/leads-workbench.ts:667

WB-COL-1: defaults + every column whose enrichTypes intersect the goal's researches, additive, COLUMNS render order preserved. The auto-show mechanism is the same computation keyed off a run's purchased tokens instead of the goal — the precedent (and the ordering rule) already exist.

LiveRunGate detects the terminal transition and emits enrich-finished with NO payload
modules/agency-portal/discover/components/LiveRunGate.tsx:151

`if (isTerminal(p.status)) { setLive(false); emitEnrichFinished(); deferOrRefresh(); ... showToast('Enriched N leads') }` — this is the exact hook point for auto-show, but the event (enrich-sheet-bus.ts:130-141) carries no types, so the listener can't know WHAT was bought from this event alone.

The purchased enrichment-type tokens ARE known client-side at run launch, and the workbench already holds them until the finish event clears them
modules/agency-portal/discover/components/EnrichMoreSheet.tsx:384

emitEnrichScope({ businessIds, types: [...enrichments], all }) fires with the exact resolved tokens; LeadsWorkbench stores them in `enriching.types` (LeadsWorkbench.tsx:816-831) and clears on enrich-finished (:833). So at the finish moment the same-session workbench knows the basket — but this dies on reload, and runs last minutes-to-hours (realtime-runs-adr), so a reload-surviving fallback is needed.

The progress endpoint already fetches the run row but does not return the purchased types
app/api/agency/runs/[id]/progress/route.ts:66

prisma.enrichmentRun.findFirst selects status/units/credits — `enrichmentsJson` (prisma/schema.prisma:2271) sits on the same row. Adding it to the select + the terminal payload gives LiveRunGate server-truth types at the terminal tick for ~zero cost (one extra JSON column on an already-made query), closing the reload gap.
