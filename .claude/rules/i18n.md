# i18n · 4 locales

Mapsly serves US + Canada. Four locales:

| Locale  | Language     | Region | Audience                                                           |
| ------- | ------------ | ------ | ------------------------------------------------------------------ |
| `en-US` | English      | US     | Default · most SMB + Agency                                        |
| `es-US` | Spanish (US) | US     | ~20% US population · esp. service categories (med-spa, hair, etc.) |
| `en-CA` | English      | Canada | Toronto + most of Canada                                           |
| `fr-CA` | French (CA)  | Canada | Quebec + Atlantic Canada                                           |

**Default:** `en-US`. Auto-detect from browser `Accept-Language` on first visit. Persist to cookie + DB user preference. Settings page overrides.

## Stack

- `next-intl` — the framework
- Translation files: `messages/{locale}.json` per locale
- Routing: `[locale]` segment in app router
- Detection: middleware reads `accept-language` and cookie

## File structure

```
messages/
  en.json          # en-US baseline + fallback for en-CA
  es.json          # es-US
  fr.json          # fr-CA
  en-CA.json       # only Canada-specific overrides (e.g. "cheque" vs "check")
i18n/
  routing.ts       # routes config
  request.ts       # next-intl server config
middleware.ts      # locale detection
app/
  [locale]/
    layout.tsx     # locale-aware root
    (marketing)/page.tsx
    (smb)/dashboard/page.tsx
    (agency)/lists/page.tsx
```

## Routing strategy

`pathnames` strategy with prefix `as-needed`:

- `mapsly.ai/` → `en-US` (no prefix)
- `mapsly.ai/es/` → `es-US`
- `mapsly.ai/en-ca/` → `en-CA`
- `mapsly.ai/fr/` → `fr-CA`

Routes are translatable too:

- `en`: `/lists` → `es`: `/listas` → `fr`: `/listes`

## Translation file structure

```json
// messages/en.json
{
  "marketing": {
    "hero": {
      "title": "Local SMBs ready to switch.",
      "subtitle": "With reasons. With contacts. Right now.",
      "cta_primary": "Get 50 free leads"
    }
  },
  "smb": {
    "dashboard": {
      "title": "Good morning, {name}",
      "kpi_mapsly_score": "Mapsly Score",
      "kpi_mapsly_score_tooltip": "Weighted composite across 6 dimensions...",
      "empty_state": "No new reviews this week. We'll show them here as they come in."
    },
    "reviews": {
      "tab_unanswered_count": "{count, plural, =0 {No unanswered} one {# unanswered} other {# unanswered}}"
    }
  },
  "agency": {
    "lists": {
      "title": "Lists",
      "today_new_matches": "{count} new leads today across your {listCount} lists"
    }
  },
  "errors": {
    "generic": "Something went wrong. Try again in a moment.",
    "dataforseo_503": "Data source temporarily unavailable. Retry in 2 minutes.",
    "rate_limited": "Too many requests. Try again in {minutes} minutes."
  }
}
```

**Rules:**

- **Nested keys** organized by route / module
- **ICU MessageFormat** for plurals, dates, numbers, selects
- **Never inline strings** in components — always `t('key')`
- **Pluralization** uses ICU `{count, plural, ...}` — see review tab example above
- **Numbers + dates** formatted via `useFormatter()` so locale-aware ("4.4" vs "4,4", "May 17" vs "17 mai")

## Usage in server components

```tsx
import { getTranslations } from "next-intl/server";

export default async function DashboardPage() {
  const t = await getTranslations("smb.dashboard");
  return <h1>{t("title", { name: "Maria" })}</h1>;
}
```

## Usage in client components

```tsx
"use client";
import { useTranslations } from "next-intl";

export function StatusPill({ status }: { status: LeadStatus }) {
  const t = useTranslations("agency.lead_status");
  return <span>{t(status.toLowerCase())}</span>;
}
```

## Middleware · detection

```ts
// middleware.ts
import createMiddleware from "next-intl/middleware";
import { routing } from "./i18n/routing";

export default createMiddleware(routing);

export const config = {
  matcher: ["/((?!api|_next|_vercel|.*\\..*).*)"],
};
```

```ts
// i18n/routing.ts
import { defineRouting } from "next-intl/routing";

export const routing = defineRouting({
  locales: ["en", "es", "en-CA", "fr"],
  defaultLocale: "en",
  localePrefix: "as-needed",
  localeDetection: true, // reads Accept-Language
  pathnames: {
    "/": "/",
    "/for-agencies": {
      en: "/for-agencies",
      es: "/para-agencias",
      "en-CA": "/for-agencies",
      fr: "/pour-agences",
    },
    "/lists": { en: "/lists", es: "/listas", "en-CA": "/lists", fr: "/listes" },
    "/dashboard": {
      en: "/dashboard",
      es: "/panel",
      "en-CA": "/dashboard",
      fr: "/tableau",
    },
  },
});
```

## Settings · manual override

```tsx
// in user settings
const updateLocale = async (locale: Locale) => {
  await prisma.user.update({
    where: { id: userId },
    data: { preferredLocale: locale },
  });
  // Set cookie so next page render uses the new locale
  document.cookie = `NEXT_LOCALE=${locale}; path=/; max-age=31536000`;
  router.refresh();
};
```

On every page load:

1. Cookie `NEXT_LOCALE` wins (user set it manually)
2. Else `User.preferredLocale` (if signed in)
3. Else `Accept-Language` (auto-detect)
4. Else `en-US` (default)

## Translation workflow

1. **English first.** Every new copy lands in `messages/en.json` first.
2. **Mark for translation.** Open a follow-up task in PLAN.md tagged `i18n`.
3. **Human translate.** No machine translation without human review (voice flattens — see `copy-voice.md`).
4. **Locale-specific reviewers.** Native speakers approve es / fr-CA copy.
5. **Fallback chain.** Missing key → fallback to `en`. Missing translation in `en-CA` → fallback to `en`.

## SEO implications (see `seo.md`)

- Every page metadata declares `alternates.languages` for all 4 locales
- `<html lang="..." />` reflects current locale
- hreflang in sitemap
- `x-default` points to `en`

## What NOT to do

- ❌ Inline strings (`<h1>Welcome</h1>` → use `t('welcome')`)
- ❌ Translate component code (translate copy only)
- ❌ Concatenate translated fragments ("You have " + n + " items") — use ICU placeholders
- ❌ Use Google Translate UI widget
- ❌ Skip pluralization (always use ICU `{count, plural, ...}`)
- ❌ Hardcode locale in URLs (always use `Link` from next-intl)
- ❌ Trust the browser locale only — let the user override

## Locale-aware formatting

```tsx
import { useFormatter } from "next-intl";

export function Rating({ value }: { value: number }) {
  const format = useFormatter();
  return <span>{format.number(value, { maximumFractionDigits: 1 })}</span>;
  // en: "4.4"  es: "4,4"  fr: "4,4"
}

export function Refreshed({ at }: { at: Date }) {
  const format = useFormatter();
  return <span>{format.relativeTime(at)}</span>;
  // en: "2 hours ago"  fr: "il y a 2 heures"
}
```

Currency:

```tsx
format.number(2999, {
  style: "currency",
  currency: locale === "fr-CA" ? "CAD" : "USD",
});
// en-US: "$29.99"  fr-CA: "29,99 $ CA"
```

## Anti-patterns

- ❌ Hard-coded English strings anywhere in JSX
- ❌ Templating with string concatenation
- ❌ Date `toLocaleString()` without explicit locale
- ❌ Currency without explicit currency code
- ❌ Translation key like `home_title` (no nesting — keys explode)
- ❌ Long keys that include the English text (defeats the purpose)
